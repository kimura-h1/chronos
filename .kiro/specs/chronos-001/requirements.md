# Requirements — CHRONOS-001: 閉じた時間的曲線（CTC）の検証

## はじめに
Gödel時空（Gödel 1949）を対象に、計量テンソルを実装し、時間的経路・閉じた時間的曲線の条件を数値的に検証し、既知の解析結果と照合する。
結果はブラウザ上の研究コンソールから操作・可視化する。比較対照としてMinkowski時空（平坦）を実装する。

記法: EARS（WHEN / IF / WHILE / THE SYSTEM SHALL）。

---

### R1. 時空モデルと計量
1. THE SYSTEM SHALL Gödel時空の計量 `ds² = 4a²[−dt² + dr² + dy² + (sinh²r − sinh⁴r)dφ² − 2√2 sinh²r dt dφ]`（符号 −+++）を実装する。
2. THE SYSTEM SHALL 比較対照としてMinkowski時空（円筒座標）を実装する。
3. THE SYSTEM SHALL 計量からクリストッフェル記号・Einsteinテンソルを記号計算（SymPy）で導出する。
4. WHEN Gödel時空のEinsteinテンソルを計算したとき THE SYSTEM SHALL 「ダスト＋宇宙定数」で場の方程式が満たされるかを検証し、ρ と Λ を導出・表示する（既知結果: 8πρ = 1/a², Λ = −1/(2a²)）。
5. THE SYSTEM SHALL 各モデルの出典（実在文献）を表示する。

### R2. 経路の分類
1. THE SYSTEM SHALL 接ベクトル u について g(u,u) を計算し、時間的（<0）・光的（=0）・空間的（>0）に分類する。
2. THE SYSTEM SHALL 時間的ベクトルの未来向き/過去向きを g(u, ∂t) の符号で判定する。
3. THE SYSTEM SHALL 各判定に浮動小数点誤差の上界を付与する。
4. IF |g(u,u)| が誤差上界以下 THEN THE SYSTEM SHALL 成功・失敗に分類せず「判定不能」とする（光的が期待される経路では「光的（誤差範囲内）」）。

### R3. 実験（CHRONOS-001）
1. **円軌道CTC検証**: WHEN 半径 R を与えたとき THE SYSTEM SHALL 曲線 {t,r,y一定, φ∈[0,2π)} が閉じた時間的曲線かを判定し、臨界半径 r_c の数値解（求根）と解析解 ln(1+√2) を比較する。
2. **測地線積分**: WHEN 初期位置・初速度（静止観測者系での速度）を与えたとき THE SYSTEM SHALL 測地線方程式を数値積分し、保存量（E, L, P_y, g(u,u)）の誤差、最大到達半径の数値解と有効ポテンシャルによる解・閉形式解（Gödel, L=0）を比較する。
3. **過去到達ミッション**: WHEN 半径・周回数・後退率・半径方向速度を与えたとき THE SYSTEM SHALL 「軸から出発→外へ移動→周回→軸へ帰還→待機」の区分的曲線を構成し、全区間で未来向き時間的かを判定し、到着時刻の差（過去へ何年か）、固有時間、固有加速度、折れ点での速度変化（ラピディティ）、理想光子ロケット質量比を計算する。
4. WHEN 目標年数が与えられたとき THE SYSTEM SHALL 必要周回数を自動計算できる。

### R4. 実験制御
1. THE SYSTEM SHALL 実験の開始・停止・進捗表示をAPIとUIで提供する。
2. WHEN 停止要求を受けたとき THE SYSTEM SHALL 計算を中断し、それまでの部分結果を「停止」として保存する。
3. THE SYSTEM SHALL 実験履歴を永続化（JSON）し、再起動後も閲覧可能にする。
4. WHEN 自動再計算が有効でパラメータが変更されたとき THE SYSTEM SHALL デバウンス後に再計算（プレビュー）を行う。

### R5. フロントエンド
1. **Research Dashboard**: 研究対象モデル、実験の実行状況、検証結果、未解決の物理的制約、過去の実験履歴を表示する。
2. **Spacetime Visualizer**: 3D（カメラ回転・ズーム）で座標図を表示し、計量から計算した光円錐、臨界面 r = r_c、実験経路、CTCの強調、座標軸・凡例・単位を表示する。モデル切替可能。3Dで正確に表せない情報（計量成分、光円錐の傾き）は2Dグラフで補完する。
3. **Experiment Control**: モデル選択、パラメータ・初期条件入力、開始・停止、結果確認、比較。
4. **Results Analysis**: 経路グラフ、計量による経路分類、CTC検証結果、数値誤差、解析解との比較、JSONダウンロード、複数実験の重ね合わせ比較。
5. 重要な判定には必ず計算根拠（式と数値）を表示する。
6. ダークテーマ・日本語UI・デスクトップ優先。

### R6. 科学的正確性
1. THE SYSTEM SHALL 全ての判定結果に「数学的判定」と「物理的実現性」を分けて表示する。
2. THE SYSTEM SHALL 物理的実現性を「未確立」以外の値で表示しない（本MVPで実現性を示す根拠は存在しない）。
3. THE SYSTEM SHALL 未解決の物理的制約（観測との矛盾、因果律保護、エネルギー条件、加速度コスト等）を一覧表示する。

### R7. テスト
1. 物理エンジン: 計量の対称性、場の方程式、r_c、測地線の最大半径の解析比較、保存量、分類、判定不能。
2. API: 実験の作成・取得・停止・ダウンロード。
3. E2E: ブラウザで実験を実行し、結果表示を確認する。
